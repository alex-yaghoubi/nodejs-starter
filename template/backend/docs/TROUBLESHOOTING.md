# Troubleshooting

Diagnose local development issues with the generated app. Use `docker compose logs db` and application console logs as needed, but **never paste secrets, raw refresh cookies or JWTs** into public issues.

## `Node.js >=20.9 required`

Use Node.js 20.9+ or 22+ and check `node --version`. The API template and generator both require a compatible runtime.

## The `create-nodejs-standard-api` command cannot be found

Before publication, use the generator from its source checkout:

```bash
node ./bin/create-nodejs-standard-api.mjs my-api --skip-install
```

The npm package has not been published. Do not assume the package can be fetched with `npx` until an actual npm release exists.

## `Invalid environment: JWT_SECRET` or `DATABASE_URL`

If generated by the CLI, a unique secret should already exist in the generated `.env`. If using the backend template without the CLI, copy `.env.example` to `.env`, configure the database URL and generate a strong independent secret. Do not reuse the template's placeholder.

## Database connection refused / `/ready` reports failure

1. Start PostgreSQL with `docker compose up -d db`.
2. Check `docker compose ps` and `docker compose logs db`.
3. Ensure `DATABASE_URL` points to `127.0.0.1` if the API is running on your host; use `db` only from a Compose container.
4. Check that port `5432` is available and that your database and credentials match the Compose example.
5. Generate the initial migrations once, review, and run `npm run db:migrate`.

## `relation ... does not exist` / database table missing

You have not applied migrations to this database, or the application is using the wrong `DATABASE_URL`. Run migrations against the intended environment using reviewed files. Do not use production as a troubleshooting sandbox.

## `EADDRINUSE` / port 4000 already bound

Stop the process that uses port 4000, or change `PORT` in `.env` and restart the app. The Docker example publishes the API only to `127.0.0.1:4000`.

## `/docs` returns 404

Swagger UI is intentionally disabled in production. In development, check `NODE_ENV=development` and `ENABLE_DOCS=true`, then restart the app. The OpenAPI endpoint is not a public production feature.

## `401 INVALID_REFRESH_TOKEN` after concurrent requests

Refresh tokens rotate on each use. Reusing an old token invalidates the session family by design; serialize refresh requests in the client across tabs and devices, clear stale local state and log in again. Do not disable reuse detection to work around a client race.

## Browser login or refresh fails due to cookie / origin / CORS

- Check the actual frontend's **scheme + host + port** against `CORS_ORIGINS`.
- The refresh cookie is HttpOnly, scoped to `/v1/auth`, and `SameSite=Strict`. It is Secure in production.
- This starter supports same-site frontend/backend deployment. A cross-site frontend requires new cookie and CSRF design. CORS alone cannot solve cross-site cookie restrictions.
- With a reverse proxy, verify canonical Host/origin forwarding. Enable `TRUST_PROXY` only for a trustworthy proxy boundary.
- For browser fetch calls requiring cookies, use appropriate client credential settings, e.g. `credentials: 'include'` for permitted same-site cross-origin requests.

## TypeScript / build errors

Run `npm install`, `npm run typecheck`, and `npm run build` in the **generated** app, not in the generator repository root. If you change the schema or dependencies, recheck generated migrations and keep package versions coherent. A syntax scan alone does not prove the full dependency build succeeds.

## Integration tests will not start

The opt-in integration suite requires a dedicated migrated PostgreSQL database **whose name ends `_test`** and `ALLOW_INTEGRATION_DB=true`. See the generated README for the precise isolated setup. Never circumvent the protection by renaming production or using production credentials.

## Docker API container cannot reach PostgreSQL

The Compose API service overrides its DB connection to the hostname `db` and depends on a DB health check. Apply migrations first and inspect `docker compose logs api db`. The Compose database credentials are for local development only.

## Still blocked?

Use the `x-request-id` returned by the API to locate correlated server logs. Include a sanitized command, HTTP status, expected behavior, actual behavior, Node version, and whether the server is host-run or container-run when opening a public issue. Exclude raw `.env`, credentials, cookies, tokens and private user data.
