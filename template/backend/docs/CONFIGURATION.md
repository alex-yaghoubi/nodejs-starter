# Configuration reference

The generator writes a unique, permission-restricted, Git-ignored `.env`. If you use the template by itself, copy `.env.example` to `.env`, replace the placeholder `JWT_SECRET`, and keep `.env` out of version control.

The application validates its environment on startup in `src/config/env.ts`. All variables below are read at startup; restarting the process is required after changes.

| Variable | Example / default | Purpose and constraints |
| --- | --- | --- |
| `NODE_ENV` | `development` | `development`, `test` or `production`. In production, refresh cookies use `Secure` and Swagger UI is disabled. |
| `HOST` | `127.0.0.1` | Listen address. Use `0.0.0.0` *inside* a container, not for directly exposing an unprotected host service. |
| `PORT` | `4000` | Integer from 1 to 65535. |
| `DATABASE_URL` | `postgres://app:…@127.0.0.1:5432/standard_api` | Required PostgreSQL URL. Local `.env` uses the example Compose DB credentials; use separately provisioned credentials in production. |
| `JWT_SECRET` | Generated by the CLI | Required secret with at least 32 characters. Each app must use a unique, unpredictable value. Never commit or log it. |
| `ACCESS_TOKEN_TTL` | `15m` | JWT lifetime. Positive integer followed by `s`, `m`, `h`, or `d`. |
| `REFRESH_TOKEN_DAYS` | `14` | Refresh session lifetime, integer from 1 to 90 days. |
| `CORS_ORIGINS` | `http://localhost:3000` | Comma-separated **exact** permitted browser origins, including scheme and port. Empty means no cross-origin browser access. Avoid `*` with credentials. |
| `ENABLE_DOCS` | `false` in schema; `true` in `.env.example` | Shows `/docs` and `/docs/json` only when `NODE_ENV` is not `production`. Disable in exposed test environments as needed. |
| `TRUST_PROXY` | `false` | Enable only behind a trusted, correctly configured reverse proxy that replaces forwarded headers. |

## Local development versus Docker networking

The host-run API uses the local URL in `.env`: `127.0.0.1:5432`. The Compose `api` service overrides `DATABASE_URL` to point to the internal service hostname `db` and overrides `HOST` to `0.0.0.0`. Do not use `localhost` for inter-container database access.

**Do not use** the example Compose database password in a public deployment. In production, supply secrets via your hosting platform's secret manager, require TLS externally, and restrict database network access. The sample Docker Compose file is for local development, not a hardened production deployment.

## Browser authentication deployment constraints

The server issues an HttpOnly refresh cookie scoped to `/v1/auth`; it uses `SameSite=Strict` and `Secure` in production. This implementation is designed for **same-site** deployments, even if the frontend and API live on different same-site subdomains. Cross-site client deployments require a deliberate redesign and security review of cookie and CSRF behavior, not merely changing CORS.

The refresh/logout endpoints also check `Origin` and `Sec-Fetch-Site` when supplied. Non-browser clients without those headers can still call these endpoints. Cookies and access tokens are different: send the short-lived access JWT as `Authorization: Bearer …` to protected resource endpoints; use the refresh cookie only for token refresh and logout.

Do not reuse the same JWT secret between different products or environments. Rotating a JWT signing secret invalidates access JWTs signed with the previous one, but it is **not** a complete substitute for revoking database-backed refresh sessions.

## Database migrations

After installing dependencies, run `npm run db:generate` when initially creating a schema migration. Review and commit the generated `drizzle/` folder in the **generated application**. On each deployment, apply already-reviewed migrations with `npm run db:migrate` before starting the new API process. Do not run migration generation independently on different production replicas.

Drizzle schema: `src/db/schema.ts`. Migration config: `drizzle.config.ts`. A rollback may require a database restoration or a separately reviewed forward-fix migration; there is no automatic down-migration promise in this starter.
